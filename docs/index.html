Private by design

Direct provider APIs. Zero third-party servers.

Usage trackers often ask you to hand over access to sensitive parts of your Mac just to display a number. OpenBar connects directly to provider HTTP endpoints from your Mac, re-using your local sessions or tokens stored safely in the macOS Keychain.

There is no OpenBar backend, account, telemetry, or analytics. The app stores only preferences, local quota caches, and explicitly provided tokens in Keychain.

Multi-provider monitoring built with privacy architecture means your credentials and usage data never touch any intermediate server.

  • No browser cookies or profile access
  • No browser scraping
  • No third-party backend or server
  • No telemetry or analytics
  • No provider CLI execution
  • No Accessibility permission
  • No Screen Recording permission
  • No Full Disk Access

FAQ

Questions, answered.

Which providers and accounts does OpenBar support?

OpenBar tracks OpenAI Codex, Claude Code, GitHub Copilot, Gemini Antigravity, and OpenCode Go. You can add multiple named accounts (such as Work and Personal) per provider, each with independent credentials and refresh state.

Where are my credentials stored and does data leave my Mac?

All requests are made in-process directly from your Mac to first-party provider HTTP APIs. Explicit API tokens and OAuth client keys are stored in the macOS Keychain under in.4nkitd.openbar. There is zero telemetry, analytics, or third-party server in between.

Does OpenBar require browser cookies or Full Disk Access?

No. OpenBar never touches browser profiles (Safari, Chrome, Brave, Edge), cookie stores, or Keychain entries from other apps. It uses standard local CLI login session files or tokens you explicitly enter in Settings.

How do I add and manage multiple accounts?

Open Integrations… from the popover or Settings window. Choose a provider, enter a label (e.g. Work, Personal), and select an existing login session file or saved token. Accounts update independently and can be toggled on or off individually.

How is OpenBar different from CodexBar Lite or Headroom?

OpenBar is the multi-provider, multi-account successor built natively for macOS. While original utilities tracked single providers or required browser scraping, OpenBar uses direct HTTPS APIs for 5 providers with Keychain token storage and zero backend servers.

How do I uninstall OpenBar?

Quit OpenBar and move OpenBar.app from /Applications to Trash. Optional cleanup: rm -rf ~/Library/Application\ Support/OpenBar and defaults delete in.4nkitd.openbar.

Is OpenBar affiliated with AI model providers?

No. OpenBar is an independent open-source utility and is not affiliated with, endorsed by, or sponsored by OpenAI, Anthropic, GitHub, Google, or OpenCode.

Installing OpenBar on macOS

OpenBar is distributed as a .zip release archive. Since it isn’t currently notarized by Apple, macOS may ask you to confirm before opening it. That’s expected, not a sign anything is wrong.

  1. Download OpenBar-0.1.0-macos-arm64.zip from the release page.
  2. Unzip the downloaded archive.
  3. Drag OpenBar.app into your Applications folder.
  4. Open Applications and launch OpenBar.app.
  5. If macOS says it can’t be opened because it’s from an unidentified developer:
    • Right-click OpenBar
    • Select Open
    • Click Open again in the confirmation dialog

Still blocked?

Open System Settings → Privacy & Security, find the OpenBar message near the bottom of the page, click Open Anyway, then confirm.

Why does this happen?

macOS uses Gatekeeper to check apps distributed outside the App Store. OpenBar isn’t enrolled in Apple’s notarization program, so Gatekeeper can’t verify it automatically. The source is public, though, so you can read exactly what the app does before you run it.
