Private by design

Your Codex login is enough.

Usage trackers often ask you to hand over access to sensitive parts of your Mac just to display a number. CodexBar Lite reads the same local session codex login already created, and makes the minimum request needed to show your usage - directly from chatgpt.com.

There is no third-party backend, account, telemetry, or analytics. The app stores only preferences and a local usage cache.

See how CodexBar Lite works without an API key.

Usage trackers that support every provider have to harvest sessions from wherever they live - browser cookie stores, the macOS Keychain, sometimes Full Disk Access. Single-provider by design means this checklist isn’t restraint. It’s architecture.

  • No Chrome or browser-profile access
  • No browser cookies
  • No macOS Keychain
  • No Accessibility permission
  • No Screen Recording permission
  • No Full Disk Access
  • No API key
  • No third-party account

FAQ

Questions, answered.

Does CodexBar Lite need my Keychain, Chrome, or an API key?

No. It reads ~/.codex/auth.json, the session your existing codex login already created, and requests usage directly from chatgpt.com. Nothing else on your Mac is touched.

Does my data leave my Mac?

Only the minimum request needed to show your usage goes to chatgpt.com. There is no third-party backend, account, telemetry, or analytics.

What if I haven't run codex login yet?

Open the app. If no Codex session exists, it launches codex login in Terminal and watches for completion - usage appears automatically once login succeeds.

How do I check my Codex usage and rate limits?

Inside the Codex CLI you can run /status, or open the usage dashboard on the web - but both require going to look. CodexBar Lite keeps your Codex usage and rate-limit reset times live in the macOS menu bar, and notifies you before you hit the cap. See the full guide to checking your Codex usage.

How is CodexBar Lite different from CodexBar?

CodexBar tracks many providers - Claude, Cursor, Gemini, Copilot, and more - and to do that it reads browser cookies (Safari, Chrome, Brave, Edge), uses Keychain access to decrypt them, and can ask for Full Disk Access. CodexBar Lite deliberately does one thing: your Codex number, from one file, ~/.codex/auth.json. It never touches your browser or Keychain. Lite is the feature, not a limitation. Read the full comparison.

How do I uninstall it?

Quit CodexBar Lite and move it from /Applications to Trash. Optional cleanup: rm -rf ~/Library/Application\ Support/CodexBarLite and defaults delete dev.vaibhav.codexbar.

Is this affiliated with OpenAI?

No. CodexBar Lite is an independent utility and is not affiliated with, endorsed by, or sponsored by OpenAI.

Installing CodexBar Lite on macOS

CodexBar Lite is distributed as a .dmg file. Since it isn’t currently notarized by Apple, macOS may ask you to confirm before opening it. That’s expected, not a sign anything is wrong.

  1. Download the latest CodexBar Lite .dmg from the release page.
  2. Open the downloaded .dmg file.
  3. Drag CodexBar Lite into your Applications folder.
  4. Open Applications and launch CodexBar Lite.
  5. If macOS says it can’t be opened because it’s from an unidentified developer:
    • Right-click CodexBar Lite
    • Select Open
    • Click Open again in the confirmation dialog

Still blocked?

Open System Settings → Privacy & Security, find the CodexBar Lite message near the bottom of the page, click Open Anyway, then confirm.

Why does this happen?

macOS uses Gatekeeper to check apps distributed outside the App Store. CodexBar Lite isn’t enrolled in Apple’s notarization program, so Gatekeeper can’t verify it automatically. The source is public, though, so you can read exactly what the app does before you run it.
