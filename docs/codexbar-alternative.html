CodexBar alternatives, compared.

OpenBar is one of several macOS menu bar apps for tracking AI usage. Here's how it stacks up against CodexBar, CodexUsageBar, SessionWatcher, and TokenBar - access required, providers supported, and price, sourced from each tool's own site.

What CodexBar does well

CodexBar is an excellent open-source menu bar app that tracks usage across 66+ AI coding providers - Codex, Claude, Cursor, Gemini, Copilot, and many more - with session, weekly, and monthly windows. If you juggle several providers and want every quota in one dropdown, it's the right choice, and this page won't pretend otherwise.

The cost of tracking everything

Supporting 66+ providers means collecting sessions from wherever each one keeps them. Per its own documentation, CodexBar requires macOS 14 (Sonoma) or later, uses macOS Keychain access to decrypt browser cookies and store OAuth credentials, and can request Full Disk Access for Safari data. All of that is documented, legitimate, and mostly optional depending on which providers you enable - but it's a lot of surface area. It's free and open source under the MIT license.

CodexUsageBar: privacy-focused Codex tracking

CodexUsageBar is an alternative that makes a similar access claim: no cookies, reading the Codex CLI session directly. It's also free and open source. Where it differs is hardware and OS support - it runs on macOS 12+ on both Apple Silicon and Intel, while OpenBar requires macOS 13+ on Apple Silicon with Sparkle auto-updates and multi-account support.

SessionWatcher and TokenBar: paid, multi-provider, access undisclosed

SessionWatcher tracks Claude, Codex, and Cursor (bundle tier) starting at $6.99 one-time, running on macOS 14+ on Apple Silicon and Intel. TokenBar tracks OpenAI, Codex, Claude, and Cursor for $5/month or $15 lifetime. Neither publishes what system access it needs to read usage from each provider - no stated position on cookies, Keychain, or API keys, and no GitHub repository to check yourself.

Two other tools are worth a mention: Codextime takes a CLI-sync-plus-public-leaderboard approach, and Usagebar is built Claude-Code-first.

What OpenBar does instead

OpenBar is designed to be native, lightweight, and private by architecture. It supports multiple accounts and integrations, reading local session files (like ~/.codex/auth.json) or secure macOS Keychain tokens, making direct requests to provider APIs. That architecture means:

  • No browser cookie scraping or browser profile access
  • Direct provider API connections (no third-party server or backend proxy)
  • Secure macOS Keychain storage for configured account credentials
  • No Full Disk Access, Accessibility, or Screen Recording permissions
  • Open source & native AppKit macOS app

You still get what matters: both rate-limit windows with reset times, multi-account tracking, threshold alerts (80%, 90%, exhaustion, credit reset), launch at login, and Sparkle auto-updates.

Which should you pick?

Track multiple AI tools and want 66+ integrations in one dropdown? Use CodexBar. On an Intel Mac or an older macOS release? Try CodexUsageBar. Want a native, open-source macOS app with multi-account support, direct provider connections, zero third-party servers, and zero browser scraping? That's exactly what OpenBar is for.
